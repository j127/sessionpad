Design notes — 02 · Cards

Direction

Every group of content is a soft card. The trick is a Box with borderStyle="round", borderColor="promptBorder" and backgroundColor="promptBorder": on Desktop it draws a filled rounded card that follows the app's mode, light grey (#cecece) in light and dark grey (#474747) in dark, because promptBorder is one of the three soft theme keys. Cards replace dividers and indentation, so the pane reads as a stack of objects you act on. The open tab is the app's black primary pill beside two bare-text tabs, which is the strongest "you are here" a Desktop Button can draw, since a colored or bold label inside a Button is ignored.

Element → mod call

accent below is the palette's theme key (claude, merged or success). isTerminal is e.surface === "terminal", which the pane already checks for the tab digits.

What differs between the surfaces

  • Cards. Desktop fills the promptBorder card softly in both modes. A terminal would fill it with a mid grey block under white text, so the mod drops backgroundColor there and the card is a grey frame drawn with the round box characters.
  • Emphasis. On Desktop the headline stands out by size (title) and the edited note by losing its fill. A terminal has one size and no soft fill, so both take the accent frame instead.
  • Tabs. Desktop: a black (dark mode: white) primary pill beside bare text. Terminal: bold accent text beside dim text, with the hotkey digits, because a colored Text inside a Button only draws there.
  • Buttons. Desktop pills; the per-note buttons are the faint dimColor pills so three per card don't shout. Terminal: [ label ], primary light blue, dim grey.
  • Type. Desktop uses the five sizes, medium and semibold, mono for times and italic for the aside. A terminal flattens all of that; only dim, bold and color remain.
  • Columns. The time column is a fixed-width Box, 10 cells on Desktop and 6 in a terminal; spaces collapse on both surfaces, so they never line anything up.

Honest costs of this direction

  • In light mode, dim text (#8c8c8c) on the grey card (#cecece) is low in contrast: the meta lines, dates and durations are faint. Dark mode is better. Nothing softer than promptBorder fills in both modes, so the only fix is fewer dim lines on cards.
  • Markdown's inline code chip is drawn on the same grey as the card, so on a note card prune:at is marked only by the mono face, not by a chip.
  • Rows in the kit center their children, so the time column sits a little lower than the summary when the summary wraps to two lines.
  • Cards cost height: each border adds about 17px above and below, so the Notes tab scrolls sooner than a flat list would.

Typography and palette

The pane's own type is fixed by the app: the system face at about 15px on Desktop and the terminal's one monospace font. The panel's font, radius and density controls change only this page's chrome (header, captions and these notes), where System keeps the chrome close to the app and Serif (Georgia) sets it apart as commentary. The three palettes are the accent theme key the pane would use, claude (orange), merged (purple) and success (green); they change the HEADLINE caption, the accent frames, the open terminal tab and the branch mark, while the primary buttons stay black or white because the app draws them. Light and dark are the Desktop app's two modes; the terminal frames are always the dark terminal.
