Design notes — 02 · Folder tabs

Direction

The pane is a folder. The open tab and the panel under it are one sheet, and the other tabs sit behind it on a thin rule. Three background steps carry the whole structure: the chrome (shaded), the open sheet (plain), and the content blocks (shaded again). That is why there are almost no outlines inside the panel. The headline gets a full-width tinted header because it is the one line in the pad that says what the session is for; everything under it is a list.

Typography

  • System UI at 13.5px: small, pane-sized text that sits beside the chat without competing with it.
  • Hierarchy comes from weight and size, not colour. The 17px bold headline is the only large text in Notes, and the 30px size is the only large figure in Workspace, because it is the one number you glance at.
  • There is one tracked uppercase caption, HEADLINE, in the accent: it names a role, not a section. Every other label is small, muted and in sentence case.
  • Things you would type (code spans, branch names, paths, the pane title) use the heading stack, which is monospace in both font options. The Mono option switches the body text too, which turns the page into a fair preview of the terminal pane.
  • Times, durations and sizes use tabular figures so the rail and the tree line up.

Palette

  • Slate (default): cool grey-blue neutrals that recede next to the chat. Indigo is kept for the headline caption and tint, the primary buttons (Add, Save, Undo), the note actions, the rail's nodes and the branch label.
  • Clay: warm paper with a clay accent, darkened a step from the brand-like clay so that small accent text clears 4.5:1 on the light background.
  • Plum: a purple accent on faintly violet neutrals.
  • Delete (error) and "stopped" (warning) are not extra palette colours. They are derived from each palette's accent with relative oklch colour, keeping its lightness and turning the hue to red or amber, so they stay in key with the palette and flip with the mode. The build maps them to the theme's error and warning colours.
  • Light mode is paper: a white sheet with shaded blocks. Dark mode is a terminal: a near-black sheet, blocks one step lighter, and an Undo bar that turns into a light strip, like inverse video.

Built from the primitives

  • Title bar and ×: the host's pane chrome, drawn here only for context.
  • Tab row, Desktop: a row Box aligned to the bottom. The open tab is a Box with borderStyle: round and borderColor set to the border colour, its bottom side turned off and its background set to the panel. The baseline is drawn by Boxes with only a bottom border on either side of it: a short stub on the left, and a growing Box on the right that holds the other tabs. The gap under the open tab is simply where no segment is drawn, so nothing has to overlap and no negative margin is needed. This is the "round-bordered Box with its bottom border removed" route.
  • Tab row, terminal: three lines of Text with box-drawing characters (sketched below), which line up because a terminal is monospace. If Box can't turn off single sides, the Desktop falls back to the same Text route.
  • Inactive tabs and note actions are Buttons. They look like plain words only if Button gets a plain (borderless) variant. Without one, the Desktop draws native buttons and the layout still holds.
  • Headline: a Box with a backgroundColor (the subtlest accent-tinted theme background) and padding, holding a bold accent Text "HEADLINE" and a bold Text for the headline. A terminal can't enlarge text, so the tinted band and the bold weight carry it there.
  • Note input: one Input with the label "New note", the placeholder "Add a note…", the submit label "Add" and 1 row. The joined Add button is the Input's own submit.
  • Undo bar: a Box with an inverse background (or Text with inverse) holding the message Text and a Button "Undo".
  • Note: a Box with backgroundColor set to the surface, padding and no border; Markdown for the text; dim Text for the meta line; then a row of Buttons with a Text "·" between them. A red Delete needs a tone on Button. Without one, Delete stays neutral and keeps its place last.
  • Edit state: an Input with 3 rows and the submit label "Save", plus a Button "Cancel".
  • Timeline: each turn is a row Box. The left column is a Text node (● ○ ·) above a Box with only a left border, or a Text column of │. The right column holds the bold time with the dim duration, a wrapping summary Text, and a dim marks Text. "stopped" is Text in the warning colour, and the branch label is accent Text in a tinted Box. Asides are italic, dim Text.
  • Workspace: dim Text labels over bold Text values. The size is bold with a dim unit, next to a Button "Refresh sizes". The tree is Text with ├─, └─ and │ prefixes; this mockup draws them as rules so they stay crisp in a proportional font.
  • Band: one Text line with "pad:" bold in the accent and the headline dim, cut to one line.
  • No images, no icons beyond Unicode characters, no hover-only UI, no animation ("measuring…" is plain text) and no shadows: depth comes only from background steps.
