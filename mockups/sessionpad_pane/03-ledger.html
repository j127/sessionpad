Design notes — 03 · Ledger

Direction

Ledger treats the pane as a keyboard tool. Hierarchy comes from alignment, weight and two background steps rather than cards and outlines: an underlined tab row, a strongly tinted headline strip, a prompt-style input, zebra rows, and fixed columns for times, durations, marks and sizes. Every action is a visible, labelled control (H, E, X, Restore, Export, Refresh) and a one-line key explains the letters, because hover tooltips don't work in the Desktop app.

Typography

  • Mono (default) is one face at a fixed advance, so the columns line up by construction and the Desktop pane looks almost exactly like the terminal pane. Sizes stay between 10.5 and 13px, and hierarchy comes from weight and color (bold and accent for the active tab and the headline, muted for metadata) rather than size, because a terminal has only one size.
  • Sans sets prose (notes, summaries, labels) in system-ui. The heading stack is this direction's "figure face" and stays ui-monospace in both options: it carries times, durations, marks, sizes, paths, code, the hotkey digits and the H E X letters. Sans mode therefore reads like the Desktop app while the ledger columns keep their alignment.

Palettes

  • Graphite (default): neutral grey with a teal accent. Teal reads as "selected" without the alarm of red or the caution of amber, so both stay free for X and "stopped".
  • Amber: an old phosphor terminal. Its warning tone moves to a pale yellow so "stopped" doesn't blur into the accent.
  • Clay: a Claude-like clay (#c96442 in light). Its error tone moves to a cooler crimson so a red X still reads apart from the accent.
  • Only two neutral steps are used: zebra (surface mixed with 5.5% text) and shade (11%: day rows, buttons, the input), plus two accent tints (10% for the edit row, 20% for the headline). Mixing from surface and text makes the zebra darker in light mode and lighter in dark mode with no per-mode CSS. Error and warning live in the palette blocks as --tone-error and --tone-warn; in the real pane they are the theme's error and warning colors.

How each piece maps to the primitives

  • Pane title bar ("sessionpad ×"): drawn by the host, meaning Desktop's docked pane header or the terminal's own frame. It's shown here only for context.
  • Tab row: a row Box. Each tab is a column Box holding the pressable label (a Button, or whatever the pane uses for tabs today) and, under it, a Box of height 1 row with backgroundColor = accent when active and none otherwise. In a terminal that bar can just as well be a Text of ━ in the accent. The full-width rule is a Box with a single bottom border in the border color, or a Text of ─. Active label: Text bold + accent. Hotkey digit: Text dim.
  • Headline: a Box with backgroundColor = accent tint, holding Text ▌ in the accent and Text bold. No border.
  • Note input: an Input with label ›, placeholder "Add a note…" and submit label "add ⏎", inside a Box with the shade backgroundColor and no borderStyle.
  • Key line: a row Box of two Texts: dim "4 notes" and a dim key with the H, E and X letters bold (X in the error color).
  • Notes: one row Box per note, with backgroundColor alternating between the surface and zebra colors. Markdown carries the note text, a dim Text the time · author suffix, and three Buttons labelled H, E and X. X takes the error color where the button allows it. If Desktop's native button can't be tinted, X stays a plain button and the key line still carries the meaning; in a terminal, [ X ] is red.
  • Edit state: the row's backgroundColor switches to the soft accent tint. An Input with rows = 3 is prefilled with the note and has submit label "save"; a Button "cancel" and a dim Text "⏎ save · esc cancel" sit beside it.
  • Recently deleted: a Button "▾ Recently deleted (1)" toggles a Box holding a zebra row (dim Text, Button "Restore") and a dim Text "Kept until the session ends". The dim text stands in for strikethrough, which Text doesn't offer.
  • Timeline: a header row Box (Text bold, Button "Export") and a dim key Text. Each turn is a row Box of fixed-width Boxes: time (5 cells) and duration (6 cells), both right-aligned with justifyContent flex-end; summary with flexGrow 1, wrapping; marks at 9 cells, right-aligned. The rows alternate backgroundColor. A day row is a Box with the shade backgroundColor, a bold date and a dim weekday. An aside is an italic dim Text spanning the row. A branch switch adds a second row Box under the turn, holding only an accent Text pushed to the right.
  • Workspace: key/value row Boxes with a label Box 9 cells wide (dim Text) and the value Text. The path is cut at the start in code ("…" plus the tail), since Text can't truncate from the left. Refresh is a Button. "Other worktrees" has a dim header row with a single bottom border, then alternating rows of branch | path | size, with size right-aligned in a fixed Box; "measuring…" is accent + dim, and "unavailable" is dim.
  • Band: one dim Text, with "pad:" bold.
  • Nothing here is hover-only, animated or shadowed, and the only symbols are Unicode characters (› ▌ ▸ ▾ ⏎ → … · ×).

In a terminal

Because the default face is already mono, the terminal pane is nearly the same picture cell for cell. Background colors carry the zebra rows, the headline strip and the day rows, and the 3px tab bar becomes a full row of ━ under the active tab. Buttons become [ label ], so H E X take 15 columns; below about 44 columns they drop to their own right-aligned line under the note. Rounded corners disappear.
